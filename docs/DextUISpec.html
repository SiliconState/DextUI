Architecture &
operations handbook

How DextUI actually works, where its state lives, what its guarantees mean, and how to maintain it without losing the user's work.

Implementation referenceAgentLink v1Baseline 6d1b4a2Reviewed 2026-10-05
Not a proposal. Not a production inventory.This handbook describes the checked-in implementation and its verified tests. It does not assert which services, providers or external binaries are running on a particular machine. Source and executable tests take precedence; deployed paths and versions must be inventoried separately.

DextUI is a browser/PWA control surface for dext. It presents conversations, approvals, files, reports and orchestration. The Node host agentlinkd connects the browser to local agent processes. dext owns reasoning, models, tools, policy and resumable agent history. There is no second thinking engine inside the UI.

Understand the system →Runtime topology, trust boundaries, process ownership and durable state.Operate an installation →Configuration, supervision, safe releases, rollback and recovery.Read the guarantees →Acceptance versus completion, reconnect, bounded deduplication and expiry.Diagnose a failure →Runbooks for missing builds, stuck turns, lost acknowledgements and external executors.

The supported posture is one trusted operator under one host OS account, with several tabs/devices and sessions. No tenant database, multi-user ACL, built-in TLS, HA replica or hosted billing service exists here. Separate users require separate processes, roots and OS isolation, not an assumption that the pairing token is a tenant boundary.

01 / System model

One agent. A separate control plane.

The host is a zero-dependency Node process. The app is Svelte 5, built with Vite. Protocol types and client projection live in framework-free TypeScript packages. Optional crew, mesh, git and rclone binaries do the execution they already own.

Ownership rules

  • Browser: drafts, preferences and rendering. It does not declare an authoritative task complete.
  • Host: session IDs, sequence numbers, routing, UI journal and control-plane adapters.
  • dext: model/provider access, tools, sandbox/approval enforcement, packs and seat history.
  • Crew: worker lifecycle, attempts, manifests and continuation launch. Host observations must not manufacture completion.
  • Workspace: ordinary user files. Deleting a chat is not permission to erase its directory.
A directory name is not an execution boundary.The production host imports WebSocket framing and its snapshot fold from packages/mock-server/src/. These are production dependencies even though the same package also supplies the fixture host.

02 / Persistence

Three stores, not one transcript database

UI history, agent context and workspace effects are independent. Recovering one does not reconstruct the others. A complete backup includes STATE_DIR, DEXT_HOME, any alternate seat/log roots and user workspaces.

Durability is not a database transaction.Ordinary journal/index writes do not explicitly fsync. Recovery fences, timer acceptance and kept-fork persistence use strict fsynced paths, but are not a transaction across host, core and external effects. Live ordinary execution can continue after an append failure; cmd_ack may report durable:false. Atomic rename prevents torn readers, not all power-loss scenarios.

Retention and restoration

The host keeps normal session journals in process memory. There is no host-wide live-child quota, idle-child reaper or automatic live journal archive. The 64 MiB cap is a lossy restoration operation, not a live RAM/disk cap. Preserve full journals before restarting if complete audit history matters.

Malformed journal lines are skipped; an incomplete final line is fenced before later append. A malformed sessions.json can leave sessions unrestored despite existing journal files. No orphan-journal importer is provided. New state paths do not mean old data was deleted.

03 / Boot contract

Discover capabilities before accepting work

Use a toolchain-supported Node release, preferably Node 22 LTS ≥22.12 or Node 24 LTS. Respect the lockfile's Vite/Svelte engine ranges. npm and a compatible dext executable are required. Cargo/Rust, Chromium and optional external tools are required only for the features or tests that invoke them.

  1. Resolve configuration. Validate cwd, port and approval policy. A missing workspace fails with a creation hint; a file fails as not a directory. Startup never creates a workspace implicitly, and both refusals precede agent probes and durable state creation. Resolve explicit dext, the conventional release binary, then PATH.
  2. Probe the agent. Read help, model/provider metadata and packs. NDJSON and pack UI are negotiated independently.
  3. Construct adapters. Discover crew/connector tools, gallery, tasks, triggers and self-edit support.
  4. Restore durable state. Validate roots; restore sessions cold, terminate unfinished work visibly, retry cleanup intents.
  5. Start watchers and serve. Watch known roots and build/restart changes, start trigger ticks, bind loopback.

04 / Agent lifecycle

Session identity survives the child process

A host session stores a title, cwd, random dext seat, provider/model, effort, approval policy, generation and journal sequence. The sess_... identifier is not a browser tab, provider conversation ID or child PID. Working and compacting are lifecycle flags, not separate durable identities. The index also records working-turn evidence and a nonce for opt-in crash recovery; background compaction status stays ephemeral.

Persistent bridgedext --input ndjson --output stream-json. Warm child per used session. Wait for ready, send framed user/steer/control/permission input. Supports live steering, approvals, model switching and native compaction when advertised.
One-shot compatibilitydext -p --output stream-json. Prompt on stdin. New child per turn; protocol-complete turns arm seat resume. Model locks after history. Mid-turn follow-ups queue for the next turn.

Input, ownership and policy

Bridge writes refuse encoded frames above 256 KiB or queued stdin above 1 MiB before writing; write(false) would already enqueue bytes. Host outer prompt validation allows one million JavaScript characters, so accepted outer input can still exceed the lower bridge bound and fail. Split UTF-8 stdout is decoded safely on the persistent path.

Moving cwd or changing model between turns can recycle the child while keeping seat history. After a folder move, the host locates the prior seat session explicitly; bare project-scoped resume may not find it. Approval changes apply at the next appropriate spawn/boundary. One-shot ask has no interactive permission transport through this UI.

Stop, clear and delete are different

  • Stop: interrupt active work; keep draft/history. Bridge interrupt escalates to group signals if stuck. Idle Stop does not needlessly kill a healthy warm child.
  • Close: stop the child, preserve journal and seat, return cold.
  • Clear: purge seat-owned state and journal, rotate seat/generation; preserve title/folder/settings/files.
  • Delete: purge owned history and index; preserve workspace, uploads, task/flow files and reports.

Persisted cleanup intents, epoch checks and generation resets guard crashes and late child output. A failed purge remains retryable and blocks ordinary session use; boot retries pending intents.

Interrupted turns, kept forks and background summaries

Restart recovery is off unless --auto-resume or its environment setting enables it. A persisted working turn plus an unfinished journal and valid nonce are required. The host saves an attempt fence and accepts a fixed resume:<turnNonce> prompt once. A second crash in recovery cannot loop; deliberate stops, idle/background-only sessions and legacy entries without evidence do not resume. Recovery starts a model turn on the durable seat; it never automatically replays tool calls.

A compatible core exposes session_fork. session.fork {id,at_seq?} makes a new kept seat/session from an idle saved checkpoint. An exact complete-message identity maps the optional host sequence; ambiguous or compacted-away selections fail closed. Core rounds pair-unsafe cuts backward. Source history stays unchanged; no provider request, approval/usage/nonce state or background job is inherited. Fork commands are live-only and not replayed from the client outbox.

Background compaction runs under core ownership. Its separate background_compaction v1 lifecycle does not set working or legacy compacting. Only a committed application publishes history/context and a collapsed summary; authoritative session usage accounts the work, and post_compact observes installed summaries only. Stop cancels background-only work while keeping the warm bridge. Child/session/job fences prevent stale badges and duplicate application.

See the durable contracts and exact verification gates. Manual compaction reserves session admission before awaiting bridge readiness; cancellation and old timeout callbacks cannot advance a later operation.

Approvals and provisional thinking

Core permission resolution is the receipt, not the button click. read_image cards disclose pixel sharing. Stale requests fail/already-resolve; child exit clears pending approval as denial. Crew escalation answers are not tool permissions.

Thinking preview blocks remain provisional until thinking_preview_committed. Discard events remove only the aborted attempt, preserving committed reasoning. Both folds must implement this transaction consistently.

05 / Distributed state

Accepted is not completed

cmd_ack confirms host acceptance or duplicate acceptance for nonce-tagged prompt/steering/slash commands. It does not certify provider success, tool writes or final deliverables. User action, host acceptance, core execution and workspace effects are separate stages.

Rejected commands return an error correlated to the exact original command/nonce, never a success acknowledgement. Refused slash/pack commands remain refused on nonce replay; duplicates of a still-pending asynchronous command do not claim acceptance prematurely. Legacy hosts without error nonces can correlate only one unambiguous outstanding command kind.

Three independent timeout policies

  • UI acknowledgement recovery: 20 seconds. Restore sent text only into an empty draft, cancel replay and offer a deliberate new-nonce retry.
  • Connection offline queue: 32 frames, 120-second age cap, memory-only. Replay queued frames after hello with original nonces, not every already-sent frame.
  • Host dedup registry: 4096 entries with one-hour pruning/restoration policy. Only accepted prompt nonces found in retained user-message records are reconstructed after restart.
Do not promise exactly-once work.Slash/steering/rejection entries do not have the same restart durability as journaled prompts. A new nonce can repeat external actions. After an ambiguous timeout, inspect transcript and files before retrying.

Journal and replay invariants

Data-plane envelopes carry per-session monotonic seq; control replies omit it. Snapshots describe the existing tail and must never consume a new sequence. The host replays retained suffixes when allowed, otherwise snapshots. Client drops duplicates and quarantines known gaps pending a fresh snapshot.

{"v":1,"session":"sess_123","seq":42,
 "ts":1791070000000,"event":"text_delta","data":"example"}

Changed host instance resets client stores. Session lists are authoritative for missing sessions and clear generations. A reconnect does not restart the child just because a tab went away. Current ephemeral pack UI is re-emitted during recovery.

Reconnect uses exponential backoff up to 15 seconds. Application ping interval is 25 seconds; 75 seconds without pong closes a half-dead connection. Failed hello ends automatic retry. Error-to-delivery correlation currently resolves by command kind only when a single pending match is unambiguous.

07 / Security model

Trust the operator, isolate generated content

  • Pairing: SHA-256 plus timing-safe comparison. Five failures in 60 seconds trigger a global 30-second lockout. Token grants powerful host/workspace control, not a read-only role.
  • Exposure: loopback only; no independent WS Origin allowlist, multi-tenant ACL or native HTTPS. Proxy/TLS/access policy is an operator obligation.
  • Storage: host roots/files have creation modes and feature-specific symlink checks. Existing permissions are not uniformly repaired; workspace files are not a secret vault.
  • Secrets: host prints pairing token at boot; browser stores it. File query tokens can leak through history/logs. Protect service logs, backups, screenshots and app origin.
  • Fetch: public HTTP(S) only, no credential URLs, private addresses or nonstandard ports; redirects revalidated. Residual DNS-rebinding/time-of-check risk remains.
  • Agent: UI file confinement is not dext's complete sandbox. Agent tools/pack helpers operate under core policy and the host OS account.
Do not weaken the sandbox to make an artifact work.Self-contained reports are supported. Server-backed apps and remote dependencies are not magically sandbox-compatible. Inline hostile scripts can still consume CPU/memory; structured-clone work occurs before postMessage validation.

Implementation evidence: auth / upgrade / file headersfetch guardsviewer CSP

08 / Presentation

Projection first, UI second

SessionStore is the framework-free fold. state.svelte.ts owns app connections/catalogs/preferences/delivery recovery; feature rune modules own editor/sheet state. useSession coalesces updates to an animation frame, with a 100 ms hidden-tab fallback.

Scrollback starts with the newest 300 blocks and lets the user request older history. This bounds rendered DOM, not all client/host memory. Raw recent events and tool output tails have separate bounds. Markdown is parsed into escaped typed components; charts, tables, diffs, files and tool groups reuse native renderers rather than trusting output as DOM.

Phone contract

≤600px: one nearly edge-to-edge rectangular composer, 44px controls, about 58px empty height. ≤900px: off-canvas inert-when-closed session drawer with visible-enabled focus boundaries. Touch Return inserts newline; explicit Send/Queue or Ctrl/Cmd+Return submits. Empty closed Todos is quiet but accessible through Finder. Visual viewport and safe-area handling are implemented; physical iOS/Android behavior remains manual acceptance.

Notifications and shell caching

Notifications use the browser constructor while hidden and opt-in, deduplicated from event taps. Platforms that reject it are tolerated. No server Web Push/VAPID implementation exists. An installed PWA does not guarantee notifications when closed.

The service worker caches only allowlisted shell/icons/assets, network-first, keyed by build ID. Live APIs/session files/packs are not cached. Cache cleanup occurs on activation. Offline shell availability is not offline execution or durable offline transcript storage.

Extension registry

ext/*/index.ts eagerly registers fences, panels, Finder commands, local slash handlers and flow-node metadata. Current folders are CSV, flow and task. Extensions are trusted compiled code, not sandboxed downloadable plugins. Client flow-node registration does not add host validation/execution by itself.

09 / Deliverables

Files stay in the workspace

Uploads are raw-body POSTs into <cwd>/uploads, sanitized to basenames and unique collision suffixes, never overwritten. Failed partial uploads are cleaned up. Link fetches have four-redirect, 15-second header and 120-second overall bounds. Removing a chip does not remove the uploaded file.

Host file previews are allowlisted, realpath-confined, ≤64 MiB and private/no-store. Office/ODF is attachment-only; PDF uses the browser viewer. HTML in the app is fetched by trusted code into the native artifact sheet, with a compact chat launcher.

Report loading

The viewer fetches ≤8 MiB HTML and inlines bounded same-session images. It injects restrictive CSP and light/dark/dim theme, then supplies token-free srcdoc to an opaque iframe. Ordinary network/forms/base URLs are blocked. Reports must preserve authored theme behavior; changing theme remounts the iframe, not arbitrary edits of report code.

Explicit state handshake

  1. Request. Trusted Save state sends a random request ID to the selected iframe; five-second response deadline.
  2. Validate. Match iframe/source/request and bounded JSON object/array (≤1 MiB); unsolicited messages are ignored.
  3. Review. Show user the snapshot; no write until confirmation.
  4. Write. Authenticated upload to a unique state filename. A 15-second save timeout is ambiguous: check uploads before retry.
  5. Restore. User selects a local JSON file; send only to the same current report/generation. Report support is required.

There is no report autosave, token access, report-selected path or executable state restoration. Downloads are original files and are outside the viewer trust boundary once opened elsewhere.

PNG/JPEG/WebP ≤20 MiB gets explicit native read_image guidance. dext core owns image sanitization, capability validation, two-image turn limit and provider disclosure. Uploading an image is not permission to share pixels automatically.

10 / Abilities

Catalog-driven execution, not UI-owned agents

The host prefers dext's JSON pack listing, falls back to verbose text, merges sanitized PACK.md/gallery metadata and publishes commands/unmet requirements. Watched roots are user shelves/packs plus boot-workspace local roots; command-driven refresh covers environments without recursive watching.

/pack run validates catalog name, task and active profile. Unique near matches are visibly corrected; ambiguity returns candidates. Management/create/edit actions are explicit and path/type/size confined. Packs execute through normal dext turns, not a parallel UI reasoning service.

Consumer business packs

Six shipped Rust runtime cores use a shared SDK: receipts, invoice, reconcile, cashflow, taxprep and followups. They store plain records in corresponding hidden workspace folders. Money uses integer cents. TS panels where supplied render runtime results. Installing/building the web app does not install these packs; follow the pack build/install guide.

Pack UI is independently negotiated

  1. Bridge help and ready payload advertise supported UI frames/protocol; host supplies form/progress capabilities.
  2. Core emits bounded ui.request; host validates baseline schema.
  3. Progress is auto-acknowledged and displayed without chat; forms become a dedicated sheet/pending decision.
  4. Answers use the live socket only, never reconnect outbox. Failed send/ack keeps the form editable.
  5. Current requests/progress recover on subscribe, but answers/progress are unsequenced and unjournaled. Runtime effects may still persist workspace data.

Unsupported forms need pack fallback, not fabricated success. Unknown form fields/options and invalid responses are refused; this is not arbitrary HTML execution.

11 / Coordination

Shared records. Sequential flow execution.

Tasks are the shared coordination record

Host and agent use the same .dext/tasks/*.task.json. Host assigns revision, validates then renames, and watches changes. expected_rev prevents stale overwrite; blocked requires a question; answering unblocks. Done needs at least one passing recorded check. A direct file writer can bypass write validation, so read projection marks unsupported done claims as unverified. Check fields are evidence records, not independent cryptographic verification.

Flow source and revision

Pack, prompt, gate, message and condition nodes compile into topologically ordered sequential crew tasks with {previous}. Conditions are soft human gates, not automatic branch pruning. Gate behavior depends on escalation handling; message nodes depend on mesh.

The editor saves before Run and carries saved mtime-derived revision. Supplied stale revision is refused. Specs are unique; launch record tracks starting then started on process exit 0 or failed. Initial started:true means spawn acceptance. Check external crew compatibility and deliverables separately.

One-shot timer files

With timers explicitly enabled, an agent writes <cwd>/.dext/timers/<name>.timer.json containing {rev,at,session,prompt}. Bare at/session/prompt starts at revision 1; later edits increase revision. Timestamp needs an explicit timezone, session is the host sess_... identity in the same workspace, and files are regular non-link files at most 128 KiB. Startup catches up overdue timers; busy sessions retry a later tick instead of steering a live turn.

Accepted revision/fingerprint refuses stale or same-revision changes. File deletion/rescheduling and host shutdown invalidate queued dispatch. Fsynced prompt acceptance plus permanent journal nonce dedup closes normal scheduler completion-loss windows, not arbitrary external-tool transactions. Corrupt scheduler state fails closed. See timer validation, cancellation and restart guarantees.

Scheduling semantics

Known workspaces are bounded to 64. Schedule tick: 30 seconds; filesystem debounce: 5 seconds; mesh poll: 15 seconds; cooldown: 1 minute. Local daily schedules use calendar arithmetic for DST. Flow launch is serialized; events while busy/cooling coalesce. Failures back off from 30 seconds to 30 minutes. Successful schedule slots are persisted to avoid normal restart refiring.

Retry is not external-effect rollback.Plain scheduler JSON is not a transactional job database. A failed launch may have already acted. Retry may repeat side effects; pair-token changes invalidate derived webhook tokens. Stop ingress and review outcomes before enabling retries after restore.

12 / External workers

Observe worker truth; never infer success from silence

Crew adapter scans known roots, presents bounded summaries/details, selected-worker logs/events, artifacts and stop/resume. Workers are not automatically durable chat sessions. Event replay identity is run/worker/attempt/seq; log identity is generation/offset. Selection/hiding/disconnect releases subscriptions; stale frames are rejected by subscription identity.

Replay is bounded and signals missing ranges/rotation. Client worker projection retains at most 200 blocks and roughly 512 KiB serialized content. Event catch-up reads a bounded active-file tail, not archived segments. Log catch-up and decoder have independent cursors/bounds. See the detailed worker contract.

Permission versus escalation

Interactive worker tool approval is external crew opt-in and uses a private owner-validated Unix socket with attempt/request identity. A run-level escalation answer never grants tool permission. Forwarding a response is not core's permission receipt; wait for authoritative resolution.

Foreground-owned interruption

Session Stop discovers fresh uncapped manifests by persisted core session ID and optional owner:{session,call_id,mode}. Only pending/running/paused foreground owners match; background, terminal, unrelated and legacy unowned runs survive. Portable custom/keyed IDs participate, and manifest paths distinguish colliding display IDs.

The host awaits coalesced crew stop <manifest> with a 45-second bound before signalling the captured parent. Reviewed abort hooks require crew's explicit --allow-verify; cleanup failure warns and is not proof everything stopped. Prompts, steering, timers and management cannot advance that session during cleanup. Child/bridge/epoch/turn fences keep a delayed stop from killing a replacement. See owned-stop contracts and real-crew acceptance.

Continuation

Crew launches attempt-specific user-systemd continuation units and writes owner records. Host queries only the manifest's current unit, writes separate continuation-observed.json, reports supervisor failure/unknown state, and does not relaunch on restart. Missing unit after grace can fail; unavailable supervisor remains unconfirmed, not successful.

Producer, supervisor and installed CLI compatibility are external. Submitting a unit, accepting an answer or observing a quiet log does not prove completed output or transactional per-worker checkpoint recovery.

13 / External data

Materialize folders; keep credentials separate

Selectable cwd is confined to picker root with no hidden/symlink traversal, plus known boot/workbench exceptions. Folder moves happen between turns. UI confinement does not redefine core filesystem policy.

GitHub / gitClone, fast-forward pull and explicit commit/push. Git token through askpass/environment, not argv/remote URLs. Broad staging excludes .dext/.crew but is not a secret scanner.
Drive / Dropboxrclone copy into Connected/<label>, not bidirectional conflict resolution. OAuth loopback tickets/relay are constrained; rclone owns remote tokens/config.

Registry connectors.json and rclone config live in DEXT_HOME, materialized folders under picker root. Audit remote/local divergence and pushes explicitly. No background sync guarantee or safe force-reset is implied.

Three credential domains

  • Pairing token: controls UI-to-host access.
  • Provider credentials: managed by dext auth; browser receives sanitized markers, not values.
  • Pack/connector credentials: validated host writes, protected files; pack declarations constrain names and core scrubber constrains tool visibility.

Host process environment wins over pack store. Pack names cannot set DEXT-prefixed variables. Secret values do not return in status or enter normal chat journal through credential control. They can still be exposed by malicious trusted code or user-generated workspace content; protect binaries, packs and backups.

14 / Release engineering

Promote a verified build, not half-written assets

Clean local setup

npm ci
npm run build
npm run typecheck
npm test
npm run serve -- --cwd="$HOME/my-project" --approval=auto-read

Build workspace outputs before cold-checkout typechecking. For development, mock listens on 8787 and Vite on 5173, but committed dev proxy covers /ws only. File/upload/Todos/self HTTP routes are not automatically proxied. Test full surfaces with a built app on mock/real host, or deliberately configure a complete development proxy.

Managed promotion

npm run ui:build -- --tests
# CLI rollback of an available last-known-good build:
npm run ui:rollback

Direct npm run build writes generated outputs in place and does not supply managed production rollback safety. Managed builder uses a checkout lock, per-run staging, tests/checks and promotion rollback. LKG only exists after deliberate provisioning or promotion; it is not an unlimited release archive.

Process supervision template

The repo does not install a service. Use an OS supervisor for a persistent host. This is a Linux user-systemd template, not a detected deployment. Replace paths, protect the environment file as 0600 and provision a stable pairing credential.

[Unit]
Description=DextUI agent host
After=network.target

[Service]
Type=simple
WorkingDirectory=/absolute/path/to/DextUI
EnvironmentFile=%h/.config/dextui/agentlinkd.env
ExecStart=/absolute/path/to/node /absolute/path/to/DextUI/packages/agentlinkd/src/server.mjs --cwd=/absolute/path/to/workspace --state-dir=/absolute/path/to/host-state
Restart=on-failure
RestartSec=2
TimeoutStopSec=15

[Install]
WantedBy=default.target

Set service PATH/DEXT_HOME intentionally. Self-restart exits 75 so Restart=on-failure works; without supervision, restart merely ends the process. Nonforced restart waits for turns, manual/background compaction, cleanup/management/forks, starting flows, builds and fresh uncapped crew activity. Unknown continuation state is not idle; a stop remains busy even if its manifest disappears. Operation/build/hidden-run completion wakes a pending request. The 250 ms notice delay rechecks activity before shutdown, coalesces requests and honors cancellation. This is not a general barrier for every connector or external process; operators must still quiesce independent writers. Forced restart is an explicit override and can terminate work.

Release checklist

  1. Record revision, Node/dext/crew versions, configured roots and deployed build ID.
  2. Stop new ingress, wait idle, back up before migrations/host changes.
  3. Review dependencies, install under intended account, run verification.
  4. Promote managed build; verify build-id and authenticated self status.
  5. Web-only: refresh, no host restart. Host change: supervised idle restart; clients resnapshot and sessions return cold.
  6. Confirm health, authentication, a controlled turn, durable journal and actual output.
Safe-mode path stays fixed at boot.A host serving selected LKG remains pointed there until restart/configuration repair, even after new dist is promoted. Rollback consumes LKG into dist and does not revert host/dependencies/state. No generic state migration framework exists.

15 / Data operations

Quiesce writers. Restore matching state.

There is no automated consistent-backup endpoint. Browser drafts are not included in host backup, and a checkout or dist archive is not conversation backup.

Backup

  1. Stop new launches and webhook ingress; review pending scheduler retry/slot state.
  2. Wait for idle, stop supervised host and quiesce external dext/crew writers sharing roots.
  3. Archive STATE_DIR, DEXT_HOME, alternate seat/log roots, connected folders and relevant cwd data together.
  4. Preserve ownership/permissions, avoid accidental symlink traversal, encrypt remote copies.
  5. Test recovery to a separate account/location before claiming backup success.

Restore

  1. Preserve damaged state for forensics; do not clear/delete to “fix” history.
  2. Restore matching host index/journals, dext seats and workspaces with compatible executables.
  3. Start isolated loopback port with a deliberate token; inspect startup errors and paths.
  4. Check expected sessions cold, journal tails, cwd and controlled seat resume.
  5. Review unfinished-turn failure markers and already-landed side effects.
  6. Enable ingress/schedules only after external effects and retry hazards are understood.
A restart is not an undo.Seat restore does not reverse git pushes, cloud copies, sent messages or tools that ran before a crash. UI journals do not reconstruct model context; dext history is a separate store.

Routine maintenance

Monitor disk, append/index failures, long-session memory, snapshots and uploads/crew artifacts. Tool discovery is boot-sensitive: redo capability checks after binary upgrades. New scheme/host/port changes browser origin and pairing/preferences. Audit source/pack changes and connector push contents; keep secrets and scratch captures out of public commits.

16 / Troubleshooting

Collect evidence before retrying work

Collect revision, build ID, executable versions/paths, configured roots, session ID, sanitized event tail and supervisor logs. Boot logs contain pairing token; redact before sharing. Public health is not provider readiness. No metrics exporter, trace backend or availability SLO is implemented.

UI missing, 404 or stale build
Check exact static path and index.html, build/promotion result and available LKG. Use CLI/safe repair, not repeated restart. Compare build-id and reload/SW state. Clearing site data discards pairing, drafts and preferences; icon updates can require reinstall.
Pairing fails or HTTP 429
Verify stable token configuration without sharing it. Stop repeated bad attempts and wait global 30-second lockout. Random omitted token changes on every restart. Pairing, provider and connector credentials are distinct.
No acknowledgement; draft was restored
Inspect transcript and workspace first. Timeout is ambiguous, and Retry uses a new nonce. durable:false means investigate disk/permissions even if output is visible. Do not equate accepted with completed.
Reconnect loop or sequence gap
Check proxy WS support, idle timeouts, host-instance changes and output backlog. Client quarantines gap then snapshots. Do not hand-edit sequence numbers to hide missing history. Slow consumers can be dropped and recover.
Turn waits on approval or bridge cannot start
Check current capability, request identity, resolved dext binary/help and ready negotiation. NDJSON support does not imply pack UI. One-shot ask cannot receive UI permission. Deny/interrupt obsolete requests deliberately; escalation answer is not tool approval.
Provider failed but host is healthy
Inspect sanitized provider status/catalog and dext diagnostics. Resolve provider auth, quota, endpoint or network in dext. Health and cmd_ack do not validate the upstream model.
Session disappears or cleanup cannot finish
Check STATE_DIR, index parse and permissions, old roots and cleanup intent. Preserve damaged state and use backup; no automatic orphan import. Repair owned-seat/child shutdown cause and retry same cleanup, never delete the user's workspace.
Disk write or journal persistence failure
Check free space, read-only mounts, ownership and symlink refusal. Stop new work if durability is required. Live stream can outlive failed append; filesystem writes are not an fsynced transaction guarantee.
Flow accepted then failed; continuation unknown
Inspect flow launch record/diagnostics, spec and installed crew support. Check final manifests/artifacts and external effects before retry. Observe continuation's current user-systemd unit; do not relaunch just because a browser vanished or systemctl was unavailable.
Connector conflict or blank report
For connector: tool/auth/local repository state, explicit conflict resolution; do not force-push/reset blindly. For report: source, bounds, self-contained dependencies, theme and CSP. Do not weaken iframe sandbox as the default repair.
Phone keyboard or layout differs from tests
Capture browser/PWA mode, pointer type, width, zoom, safe areas and visualViewport. Chromium emulation is not actual Safari/Android keyboard certification. Verify send/queue/stop and long drafts on the physical device.

Maintainer invariants

  • Change live and snapshot folds together and preserve equivalence tests.
  • Update types, host/client handling and capability gates as one contract.
  • Preserve epoch/generation/stale revision/async response protections.
  • UI changes need desktop/mobile keyboard/focus/viewport and report-boundary checks.
  • Stage production builds; preserve attributable revisions/binaries/build IDs/backups.
  • Review exact staged paths and identity before publication; exclude secrets/runtime scratch.
  • Update this handbook with operational changes. Historical roadmaps must not silently become “implemented.”

Known non-goals and unverified areas

No HA, replicated journal, multi-tenant authorization, transactional exactly-once jobs, host-wide tool resource quotas or automated consistent backups. No generic live journal rotation or orphan importer. Flow DAGs compile sequentially. No native TLS/LAN/QR/server push. Unix worker sockets/systemd continuation constrain portability. Physical-device/PWA, OAuth, installed executor compatibility, real-provider concurrency, sustained load and closed-app notifications require separate acceptance.

Synchronous filesystem writes and snapshot folding can block Node's event loop. Socket admission cap is not agent/worker concurrency control. Measure deployed journal sizes, snapshot cost, process counts, fanout and IO before setting a capacity/SLO target.

Documentation validation is reproducible.node docs/scripts/validate-spec.mjs checks local links, anchors, SVG accessibility metadata, structural invariants and implementation-backed constants. Browser checks additionally exercise search, navigation, themes, copy, print styling and narrow screens. Neither check certifies an uninspected live installation.
